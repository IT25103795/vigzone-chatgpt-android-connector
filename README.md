# Vigzone Android Connector

An open-source, phone-local client for OpenAI's documented **Sign in with ChatGPT** and Responses API flow. The native connector can be embedded in a Trusted Web Activity without giving the web page or its server OAuth credentials. This component is separate from the private Vigzone web application.

## Availability

OpenAI currently documents ChatGPT plan usage for eligible Plus and Pro accounts. A Free identity login does not grant inference access. The connector cannot grant entitlement, bypass consent, or guarantee approval of a particular client or account. OpenAI remains the authority on eligibility, usage and distribution requirements. Publishing this component does not claim that the private Vigzone service has partner approval.

## Integration

Build as an Android library (Java 17, Android SDK 35, minimum API 23). Use `PostMessageTwaLauncher` from an existing Android Browser Helper `LauncherActivity.createTwaLauncher()` implementation. Pass the exact trusted HTTPS origin. Keep the original launcher Activity lifecycle and normal TWA fallback.

An optional `PostMessageTwaLauncher.Host` receives verified `app` RPCs and browser visibility changes. Hosts can implement task backgrounding and synchronize their existing notification preference without exposing OAuth credentials. The native hello advertises `lifecycle:1` only when that host is installed. Register `ChatGptConnector.setCompletionListener` from the host Application to deliver a completion alert directly from the saved generation job, independently of a live page. The host must enforce its active account, opt-in setting and OS notification permission, suppress foreground alerts and clear alerts on return. Callback failure never removes the encrypted reply.

`status` returns saved account availability and its optional `selectedModel` without refreshing network tokens or exposing credentials. After an existing user chooses a model, call `select` with `model` and `expectedAccount`; this stores that choice inside the same encrypted account record. A verified host can restore it on a fresh document without repeating OAuth or model-list requests. Preserve explicit switches to other providers. A transient transport/catalog failure must never be presented as an absent saved account. Restore after the host account is verified, even if the initial native hello arrived before deferred app scripts.

Call `PostMessageTwaLauncher.resumeExisting()` from an icon-entry handoff to probe a reused browser task even when Chrome omits TAB_SHOWN. Foreground-only channel monitoring retries silent ports and expired retry bursts; it stops while the tab is hidden. It never opens authentication or bypasses origin validation.

Publish a Digital Asset Links statement for the consuming app's original signing certificate with `delegate_permission/common.use_as_origin` alongside `delegate_permission/common.handle_all_urls`. A debug certificate is not trusted by the production origin. Chrome 115+ and successful origin validation are required for the message channel.

Chrome first transfers a MessagePort in an empty window message. The native `{connector:"vigzone-chatgpt",version:1,nonce}` hello then arrives on that port. Echo `{connector:"vigzone-chatgpt",event:"ready",nonce}` immediately on the same port. Bounded native retries replace an unacknowledged channel, including when a usable document is waiting indefinitely for a subresource and Chrome never sends NAVIGATION_FINISHED. Retries stop after receipt of the matching challenge. Every foreground return probes the existing channel again and recreates a silent port automatically; a browser binding restart reuses the session identity without reopening authentication. A late navigation finish probes the live port again; the page should echo repeat hello challenges without interrupting its pending RPC calls. Verify the exact event origin: older Chrome emits `android-app://HOST/PACKAGE`, while current Chromium emits the normalized `android-app://HOST` origin. Accept the latter only for the exact trusted host, a browser-trusted event and a null sender window; Chrome must still complete Digital Asset Links validation for the app. Use this port for JSON RPC: `{id,method,params:{accountId,...}}`. Methods: `status`, `login`, `models`, `chat`, `cancel`, `disconnect`, `recover`, `watch`, `ack`. Responses echo `id`; streamed text uses `{id,event:"delta",delta}`. No method returns credentials. `accountId` must identify the host's active signed-in account; keep model selection and verified connection identity scoped to that account.

`chat` requires `requestId`, `conversationId`, `model`, `expectedAccount`, `text` and optional user/assistant `history`. Up to 200 bounded history messages and a bounded untrusted `context` string can be supplied by the host. The host is responsible for account isolation and selecting relevant history. Select a model from this account's returned catalog. Search is requested automatically with `web_search` and `tool_choice:auto`; OpenAI account/model/workspace policy controls access. Public live evidence can also be supplied in context with public `sources` metadata. If the API rejects the search tool before generation, the connector retries the same account/model using supplied public evidence, without an API-key fallback. No additional host search switch or approval prompt is required.

Streamed search progress uses `{id,event:"status",status:"searching"}` and must not resolve the RPC. Completed replies include safe public `citations`, `contextSources`, `webSearchUsed` and `webSearchUnavailable`. Hosts must render citations as visible clickable links and disclose when live information cannot be verified. Only a received `response.completed` commits success. Generation runs in an Android JobScheduler job rather than the launcher Activity. Android 12+ uses an expedited job when quota permits, with a regular scheduled job fallback. Request data, first partial text, periodic progress checkpoints and completed replies (including public citations) are encrypted locally. `recover` returns queued/running/completed/interrupted state for the calling account. `watch` with the original requestId reads progress without repeating inference; running progress uses `{id,event:"snapshot",state,content}` and text deltas carry their character offset to prevent duplication after replacing a channel. A host should preserve its pending promise across a verified channel replacement, poll the same request, and reset an idle deadline on native progress rather than enforcing a five-minute total duration. Acknowledgment removes a terminal reply only after the host saves it. Interrupted text must remain visible and must not be labeled complete. Android may stop jobs or force-stop the app; interrupted inference is never automatically retried or charged twice.

The user signs in through the system browser. First registration uses `dynamic_agent_client`, a stable opaque host identifier and the consistent name **Vigzone Android Connector**. The loopback listener binds only `127.0.0.1`, validates one-time state and PKCE, and expires after five minutes. The client validates the ID token's RSA signature, issuer, audience, expiry and nonce before saving tokens. Reauthorization retains the issued client ID and account identity. OAuth credentials and completed replies use Android Keystore AES-GCM encryption with account-specific associated data, app-private storage, and no browser/server exposure. Host apps must disable credential backup.

Disconnect forgets the local connection. Users can separately revoke the registered client's access in ChatGPT settings. ChatGPT account changes must be explicitly confirmed in the host UI. No API-key fallback is performed automatically.

## Limitations

This component provides streamed text conversations and available web search. It does not import ChatGPT's own conversation history or memory, and does not expose image generation, transcription, computer control or other unsupported hosted tools. The host may supply its own relevant account-scoped chat history and saved facts. The model catalog comes from OpenAI, not hardcoded model entitlements. Real-account consent and inference require an eligible user's interactive sign-in; fake test credentials are never presented as a working connection.
